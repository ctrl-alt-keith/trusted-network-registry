# Provider Assumptions

Provider assumptions are intentionally narrow and cite official sources where
the MVP depends on external behavior.

| Assumption | Project use | Source | Checked |
| --- | --- | --- | --- |
| Linode Object Storage can be used as S3-compatible object storage and buckets are created before objects are uploaded. | Terraform provisions a private bucket; publisher output remains dynamic content outside Terraform. | [Akamai Cloud Object Storage guide](https://techdocs.akamai.com/cloud-computing/docs/getting-started-with-object-storage) | 2026-05-17 |
| Akamai Object Storage supports SDKs and tools built on the Amazon S3 API. | The publisher uses an S3-compatible Python client to upload generated registry JSON. | [Akamai Object Storage overview](https://techdocs.akamai.com/cloud-computing/docs/object-storage) | 2026-05-17 |
| Akamai documents boto3 as an Object Storage client and currently recommends SDK releases before the January 15, 2025 checksum behavior change, including boto3 1.35.99. | Runtime dependency currently allows `boto3>=1.35.99,<1.44`; treat this provider note as the upload compatibility caveat for that range. | [Akamai boto3 docs](https://techdocs.akamai.com/cloud-computing/docs/using-the-aws-sdk-for-python-boto3-with-object-storage), [Akamai AWS CLI and SDK support details](https://techdocs.akamai.com/cloud-computing/docs/aws-cli-sdks-support-details) | 2026-05-17 |
| Object Storage access keys and secret keys authenticate S3-compatible clients, and secret keys are only shown once. | The publisher reads `LINODE_OBJ_ACCESS_KEY` and `LINODE_OBJ_SECRET_KEY` from the runtime environment and never stores credential values in config. | [Akamai access keys docs](https://techdocs.akamai.com/cloud-computing/docs/manage-access-keys) | 2026-05-17 |
| Object Storage S3 endpoints are HTTPS URLs built from the S3 endpoint hostname. | `publish.endpoint_url` requires an HTTPS S3 endpoint URL. | [Akamai bucket and object URL docs](https://techdocs.akamai.com/cloud-computing/docs/access-buckets-and-files-through-urls) | 2026-05-17 |
| Objects can be private and are public only when access controls allow it. | The publisher requests a private ACL on uploaded registry objects and docs treat payloads as private by default. | [Akamai bucket and object URL docs](https://techdocs.akamai.com/cloud-computing/docs/access-buckets-and-files-through-urls) | 2026-05-17 |
| Akamai Object Storage assigns version IDs when bucket versioning is enabled; the S3-compatible boto3 `PutObject` response exposes `VersionId` when available. A literal `null` version is not a stable unique version in S3 semantics. | The publisher reports the returned usable version ID alongside the SHA-256 and byte length of its exact `PutObject.Body`. A missing, blank, or `null` ID is reported as JSON `null` and cannot pass version-specific LKE verification. | [Akamai Object Storage versioning](https://techdocs.akamai.com/cloud-computing/docs/versioning-retain-object-version-history), [boto3 PutObject response](https://boto3.amazonaws.com/v1/documentation/api/latest/reference/services/s3/client/put_object.html), [S3 suspended-version behavior](https://docs.aws.amazon.com/AmazonS3/latest/userguide/AddingObjectstoVersionSuspendedBuckets.html) | 2026-10-09 |
| The boto3 client can retry transient requests, so one application call does not prove one server-side PUT. | Upload receipts identify the response returned to this call; the publisher adds no application-level retry and does not claim exactly-once writes. | [boto3 retry guide](https://boto3.amazonaws.com/v1/documentation/api/latest/guide/retries.html) | 2026-10-09 |
| Third-party S3 tooling uses an explicit Object Storage endpoint and region values. | Publisher config requires endpoint URL and region for S3-compatible upload client construction. | [Akamai AWS CLI docs](https://techdocs.akamai.com/cloud-computing/docs/using-the-aws-cli-with-object-storage) | 2026-05-17 |
| The Linode Terraform provider supports `linode_object_storage_bucket` with `region`, `label`, and private ACL configuration. | `infra/terraform` provisions only storage infrastructure. | [Linode Terraform provider resource docs](https://registry.terraform.io/providers/linode/linode/latest/docs/resources/object_storage_bucket) | 2026-05-17 |
| The Linode Terraform provider can be configured with `LINODE_TOKEN`, `LINODE_OBJ_ACCESS_KEY`, and `LINODE_OBJ_SECRET_KEY`. | Docs recommend environment variables over committed credentials. | [Linode Terraform provider docs](https://registry.terraform.io/providers/linode/linode/latest/docs) | 2026-05-17 |
| Terraform can store sensitive variable values in state. | Security docs warn that state must remain private. | [Terraform variables docs](https://developer.hashicorp.com/terraform/language/values/variables), [Terraform sensitive data docs](https://developer.hashicorp.com/terraform/language/manage-sensitive-data) | 2026-05-17 |
| The Meraki Dashboard API is a REST API using bearer-token authorization, with the common base URI `https://api.meraki.com/api/v1`. | Live Meraki discovery reads the API key only from `MERAKI_DASHBOARD_API_KEY` and sends it as a bearer token. | [Cisco Meraki Dashboard API introduction](https://developer.cisco.com/meraki/api-v1/), [Cisco Meraki Dashboard API getting started](https://developer.cisco.com/meraki/api-v1/getting-started/) | 2026-05-17 |
| The Meraki Dashboard API requires an `organizationId` for organization-scoped operations. | Live Meraki discovery requires a private local `meraki.organization_id` selector when not using a fixture. | [Cisco Meraki Dashboard API getting started](https://developer.cisco.com/meraki/api-v1/getting-started/) | 2026-05-17 |
| `GET /organizations/{organizationId}/devices/uplinks/addresses/byDevice` lists current uplink addresses for devices in an organization, is documented with read telemetry scope, supports `Link` header pagination, and includes interfaces such as `cellular`, `wan1`, and `wan2` with `addresses[].protocol` and `addresses[].public.address`. | Live Meraki discovery calls only this read-only endpoint, follows documented next-page links, accepts only generic source refs `wan1`, `wan2`, and `cellular`, parses `public.address` with `ipaddress`, renders IPv4 hosts as `/32`, and renders IPv6 hosts as `/128`. | [Cisco Meraki Dashboard API: uplink addresses by device](https://developer.cisco.com/meraki/api-v1/get-organization-devices-uplinks-addresses-by-device/) | 2026-05-17 |
